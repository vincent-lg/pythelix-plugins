# Pythelix plugins

The central registry of plugins for [Pythelix](https://github.com/vincent-lg/pythelix),
a text-based game engine. A plugin is a package of worldlets a game can install
with one command:

```
bin/plugin install rooms
```

See [the plugin documentation](https://github.com/vincent-lg/pythelix/blob/main/docs/plugins.md).

## What's here

```
plugins/<key>/   the source of every published plugin
index.json       generated by CI, never edited by hand
ci/              what CI runs
```

Each version of each plugin is published as a release tagged `<key>-v<version>`,
with one asset, `<key>-<version>.tar.gz`.

## Proposing a plugin

Open a pull request adding or updating `plugins/<key>/`. To release a change to
an existing plugin, raise `version` in its `plugin.txt`. See
[writing a plugin](https://github.com/vincent-lg/pythelix/blob/main/docs/plugins/authoring.md).

CI checks that:

- the manifest parses and its key matches the directory;
- the version is greater than the last published one, and a published version
  hasn't changed;
- the worldlets pass the checker on the engine, the plugin's dependencies and the
  plugin;
- the plugin's scenarios pass;
- there's a `docs/README.md`, and only `.txt` and `.md` files.

Then a person reads the worldlets. Pythello is sandboxed, but a plugin can still
grant powerful commands, so the review matters.

Once merged, CI builds the archive, computes its hash, publishes the release and
updates the index. Nobody writes a hash by hand.

## Which engine CI uses

The `main` branch of Pythelix, unless the repository variable `ENGINE_REF` names
another ref.
